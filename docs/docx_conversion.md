# Word変換MVPの事前調査と設計

## 調査結果

以下は実装開始時の調査記録である。その後の実ファイル検証は [出力改善の検証メモ](conversion_improvements.md) に記録している。

入力DOCXは作業ディレクトリに存在しないため、ユーザー添付の表画像を調査した。
会社情報が表外にあり、表は「期間」「プロジェクト名・内容」「担当業務」
「環境・言語等」「役割・規模」の5列。見出しの下は1行1案件で、複数の会社の表が存在する。
内容セルには案件名、【概要】、【担当業務】があり、複数段落と改行がある。
第二画像は別レイアウトであり、期間や案件名に第一画像との差がある。
変換では入力の文字列を採用し、第二画像から値を補完しない。
この調査時点では、実物のOOXMLにおける結合や改行位置は未確認だった。

## 抽出方法とデータ構造

標準ライブラリのZipFileとElementTreeでword/document.xmlを読み取る。
表の見出しから列位置を判別し、各行をProjectとして保持する。
Projectはname、period、overview、duties、technologies、source（表・行番号）、stages（担当工程）を持つ。
Extractionは案件リスト、構造や重複の警告、氏名のマスク候補を持つ。
本文は各セル直下の段落、文字列、明示改行、タブから構築する。
案件名・概要・担当業務は明示された節見出しで分割し、担当業務の別列はstagesに保持する。表示時だけ期間・技術要素を1行化する。
マスク対象と最終テキストをターミナルで確認し、yesで承認された場合のみ排他的に作成したUTF-8ファイルへ出力する。検出0件でも確認する。

## 不明点とリスク

- 当初は実物の表構造が未確認だったが、その後、特定文書の本文直下の表を検証した（後述）。案件行の結合は前後案件の誤混在を避けるためエラーにする。
- 担当業務の2つのセルの内容は重複し得る。削除せず保持して同一行を警告する。
- 明示見出しのない概要や、表外・図形・変更履歴の情報を推測して分類しない。
- ラベルのない人名は汎用の正規表現で識別できないため、追加マスク指定と人手での確認を必要とする。
- 電話・メールの非標準表記、ラベルのない住所・生年月日などの自動マスクは網羅しない。JSON設定で対象を追加・変更できる。企業名・顧客名・案件名は自動マスク対象にしない。
- 表の見出しを認識できず、後述の継続表の条件にも一致しない場合、その表は警告して対象外になる。出力件数と警告を確認する。

## プロジェクト分離

summarize_resume 内で追加した変換機能を resume-format-converter へコピーして独立させた。
src/__init__.py と pytest.ini も含め、既存の相対importと実行コマンドを維持する。
実行時の外部ライブラリはなく、テストのみpytestを使用する。
元プロジェクトのOCR・LLM・GUIコード、.env、仮想環境、実物の職務経歴書は含めない。
元プロジェクトのファイル削除とREADMEの復元は別途承認を受けて行う方針とした。
プロジェクト分離時点では実物DOCXでの受け入れ確認は未完了だった。その後に実施した検証結果は [出力改善の検証メモ](conversion_improvements.md) を参照。

## マスク設定と保存承認の追加仕様

既存のmask_textを拡張し、検出と置換を同じ処理で行う。実データ用JSONはGit対象外とし、空の設定テンプレートのみ公開する。検出値とマスク後の全文は端末にのみ表示する。拒否・空入力・入力終了・Ctrl+Cでは出力を作成しない。元のWordを変更せず、外部通信や追加依存を導入しない。

## 実ファイル確認後の更新

直接隣接する見出しなしの継続表は、列数一致・明示的な期間・概要または担当業務の見出しを条件として前表の列構成を引き継ぐ。会社見出しなどの文章を挟む場合は適用しない。詳細は [出力改善の検証メモ](conversion_improvements.md) を参照。
